# Intelligent Backhaul Load Matching System (IBLMS)

IBLMS reduces empty return trips of commercial trucks by matching available vehicles with suitable return loads. It uses hard-constraint filtering, an explainable weighted match score, profitability estimation, and two trained ML models.

## Features

- **Five roles:** Business Poster, Individual Poster, Fleet Owner, Owner-Driver, Fleet Driver, plus a hidden Admin panel
- **Vehicle / Trip / Load management** with a known-location picker (no manual lat/lng)
- **Matching engine:** hard constraints (capacity, vehicle type, timing) first, then a 7-factor explainable score
- **Profitability estimate:** revenue, fuel, toll, profit and empty-return vs backhaul comparison
- **ML modules (synthetic training data):** compatibility classifier and profitability regression, served by a Flask microservice
- **Multi-leg (2-leg) backhaul chain finder**
- **Booking workflow:** request, Fleet Owner approval for driver requests, then the full trip lifecycle
- **Route map** with live GPS and a simulated fallback
- **Multilingual UI:** English, Hindi, Tamil, Telugu
- **Light / dark theme**

## Prerequisites

- Node.js 18+
- Python 3.10+
- MongoDB running locally (or a MongoDB Atlas URI)

## Setup

### 1. Backend

```bash
cd backend
npm install
```

Create `backend/.env`:

```
MONGODB_URI=mongodb://localhost:27017/iblms
PORT=5000
JWT_SECRET=change-me
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change-me
```

```bash
npm run dev
```

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Opens at http://localhost:5173

### 3. ML service (optional)

The app works without it and simply hides the ML badges.

```bash
cd ml-service
pip install -r requirements.txt
python app.py
```

Trained models are already included in `ml-service/model/`. To retrain, run `generate_dataset.py` then `train_model.py` (and the profitability equivalents). See `ml-service/README.md` for details.

## Demo Data

With MongoDB running, seed ready-to-use demo accounts with past trip history:

```bash
cd backend
node scripts/seedDemoAccounts.js
```

Logins are listed in `backend/DEMO_ACCOUNTS.md`.

## Admin Panel

Visit `/admin` directly. It is intentionally not linked anywhere in the UI. Credentials come from `ADMIN_USERNAME` / `ADMIN_PASSWORD` in `backend/.env`. Change them before any real deployment.

## Notes on the ML Models

Both models are trained on **synthetic data** generated by the scripts in `ml-service/`, because no real match history exists yet. Reported metrics describe performance on that synthetic test set only, not real-world accuracy. See `ml-service/model/*_training_report.md`.
